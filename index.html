💡 핵심 구현

1. 시간·장소 조율을 한 번에

날짜 범위가 있는 약속을 만들면 같은 트랜잭션에서 시간 투표와 장소 투표를 함께 생성합니다.

2. 행 잠금으로 동시성 제어

후보 추가·투표·확정 같은 약속 변경 작업을 SELECT … FOR UPDATE 행 잠금과 트랜잭션으로 직렬화했습니다. 여러 참여자가 동시에 같은 장소를 후보로 추가하거나, 확정과 투표가 겹쳐도 데이터가 어긋나지 않습니다.

3. JSONB로 유연한 투표 모델

투표의 선택지·사용자별 응답·확정 선택지를 PostgreSQL jsonb 한 컬럼(PollData)에 저장했습니다. 시간 투표와 장소 투표를 같은 구조로 다루면서 복수 선택·변경·취소를 지원하고, EF Core ValueConverter / ValueComparer로 변경 감지를 정확히 처리했습니다.

5. 제약조건으로 데이터 무결성 보장

  • (workspaceID, placeId) 유니크 인덱스로 같은 장소의 중복 저장 방지.
  • (workspaceID, userID) 유니크로 중복 멤버 방지, 약속 참여자는 복합 키
  • 초대는 7일 만료 토큰, 멤버 추방 시 기존 초대 링크 모두 폐기
  • 워크스페이스 삭제는 이름 재입력 확인 후 FK 연쇄 삭제를 한 트랜잭션으로 처리

🔥 회고

GCP VM 배포 시도

로컬에서는 Docker Compose로 정상 동작했지만, GCP VM에 배포하는 과정에서 서비스를 정상 구동하지 못했습니다. 이후, docker-compose.yml의 환경변수가 항상 우선 적용되어 CORS가 막혔다는 사실을 배우고 정리했습니다.

배운 점

  • “내 로컬에서 되는 것”과 “배포 가능한 것”은 다르며, 배포 계획을 개발 초기에 세워야 한다
  • 설정 값이 어디에서 최종 결정되는지(기본 설정 < 환경변수) 알아야 디버깅 시간이 줄어든다
  • 진행 상황·결정 기록을 팀 전체가 공유하지 못해 시행착오가 길어졌고, 이후 배포 계획·기록 관리 체계화의 필요성을 팀 회고에 반영했다

🌱 성과 & 배운 점

  • 8주 안에 모임 생성·초대 → 장소 저장 → 약속 생성 → 시간·장소 투표 → 약속 확정까지 하나의 흐름을 백엔드로 완성
  • 멘토링에서 지도 서비스 예외 상황을 원인 분석 후 재구현하고, 장소 투표 UX에 대한 팀 의견을 조율해 기존 결정을 유연하게 수정하는 협업 역량을 평가받음
  • 최종 점검에서 솔루션의 문제 해결 가능성과 활용 방향에 긍정적 피드백
  • 요청·응답 구조와 기능 경계를 사전에 합의하고 프론트엔드와 API 계약을 계속 조정하는 것이 안정적인 통합의 핵심임을 체감

💡 핵심 구현

1. 멀티 AI API 기반 파이프라인

메인 서버를 중심으로 LLM → TTS → 이미지 생성이 이어지는 처리 파이프라인을 구성했습니다. 각 AI API의 요청·응답 형식이 서로 다르기 때문에 서버에서 이를 가공하고, 클라이언트는 항상 일관된 방식으로 결과를 받도록 했습니다. 외부 API의 차이를 서버가 흡수하므로 AI 모델을 교체해도 클라이언트 변경을 최소화할 수 있는 구조입니다.

2. 동화책 페이지 템플릿 포맷 구조

생성된 글과 삽화가 정해진 위치에 배치되도록 여러 페이지 템플릿을 구성했습니다. 콘텐츠의 유형과 분량에 따라 적절한 템플릿을 선택하고, 텍스트와 이미지를 지정된 영역에 채워 동화책 페이지를 만듭니다.

3. 계층형 서버 구조

API Gateway → Controller → Service → Entity Framework 구조로 책임을 나눴습니다. AI 호출과 파일 저장은 Service 계층에서 담당해 Controller는 요청·응답 처리에만 집중하도록 했습니다.

🔥 문제 해결 / 어려웠던 점

① 처음 해보는 서버 구조 설계와 구현

  • 문제: 레이어·프로젝트 구조를 설계하고 서버를 직접 구현하는 것이 처음이라, 초기에 전체 구조를 잡기 어려웠음
  • 해결: ASP.NET 공식 문서를 기반으로 필요한 기능을 하나씩 학습·구현하고, AI로 코드 동작 원리를 확인·이해한 뒤 직접 적용하는 과정을 반복
  • 결과: 기술을 단순히 사용하는 데서 그치지 않고, 필요한 개념을 스스로 학습해 구현하는 경험을 쌓음

② 팀원 이탈 상황에서의 역할 분배

  • 문제: 팀원들이 비전공 진로 준비·인턴십으로 지속적으로 참여하기 어려워, 기획부터 개발까지 대부분을 맡아야 했음
  • 해결: 모든 업무를 혼자 처리하는 대신 팀원이 할 수 있는 일을 구체적으로 쪼개 요청 (AI API 모델 비교·테스트, UI/UX 디자인 등). 클라이언트 개발이 지연되면 직접 지원
  • 결과: 전체 개발 일정이 밀리지 않도록 조율

🌱 결과 및 배운 점

  • 팀원들과 역할을 조율하며 프로젝트를 끝까지 완성했습니다. (최종 평가: A0)
  • 새로운 기술을 공식 문서와 다양한 자료로 스스로 학습해 실제 기능으로 구현하는 방법을 익혔습니다.
  • 팀원의 상황에 맞춰 역할을 분배하고, 진행 상황에 따라 필요한 업무를 직접 지원하며 팀을 이끄는 경험을 했습니다.

🧩 ArkBlock

블록 코딩을 활용한 딥러닝 모델 레이어 교육 솔루션

딥러닝 층의 역할과 층의 구조를 만드는 법에 대한 학습을 돕는 솔루션

구분 내용

팀 구성 5인

AI에 대한 지식은 있으나 코딩 경험이 부족한 경우, 또는 딥러닝을 학습하는 과정에 있는 경우를 돕기 위해, 직관적인 툴과 교육 목적의 시각화 기능을 구현했습니다.

💭 기획 배경

"손쉬운 AI 개발 서비스 플랫폼 BlockAI"(현재 서비스 종료)에서 아이디어를 착안하여 기획·개발했습니다.

🖥 솔루션 메인 화면

ArkBlock 메인 화면 (클릭 시 확대)

사용자가 별도의 Python 코드 작성 없이 레이어 블록을 조합해 AI 모델을 구성하고, 모델 설계부터 학습용 데이터 전처리까지 수행할 수 있는 솔루션입니다.

솔루션 주요 기능 (팀 단위)

  1. 블록 기반 AI 모델 구성 – 각 레이어를 블록으로 제공해 코딩 없이 모델 구성
  2. Python 코드 자동 생성 – 캔버스에서 레이어를 연결하면 구조에 맞는 Python 코드가 실시간 생성
  3. 실시간 모델 구조 검증 – 입력·출력 차원과 파라미터 유효성을 검증하고, 잘못된 연결은 인텔리센스로 오류 안내
  4. 모델 파라미터 최적화 – 구성된 레이어·파라미터를 기반으로 학습 조건 조정
  5. 데이터셋 자동 전처리 – 모델 입력 형태에 맞게 데이터셋 전처리

🛠 담당 업무

AI 모델의 기본 구조와 레이어 간 연산 관계를 학습하고, 이를 서비스 기능으로 구현했습니다.

  • 레이어 연결 관계를 검증하는 BlockIntellisense 설계·구현
  • 데이터셋 전처리 파이프라인 BlockPreprocessor 구축
  • CNN의 Convolution · Pooling 등 레이어 연산 구현
  • Python 코드를 입력하면 해당 코드에 맞는 레이어 블록을 생성하는 기능 구현

💡 핵심 구현

1. BlockIntellisense – 레이어 연결 실시간 검증

사용자가 캔버스에서 블록을 잘못 연결했을 때 오류의 원인을 실시간으로 파악할 수 있도록, 레이어 간 연결 관계를 검증하는 인텔리센스 로직을 설계하고 구현했습니다.

BlockIntellisense 오류 유형 예시 (클릭 시 확대)
오류 검증 내용
DimensionError 현재 레이어의 출력 차원과 다음 레이어의 입력 차원이 일치하는지 검증
ValueError 레이어 간 연산에 필요한 값이 유효한지 검증. Pooling이 반복돼 데이터 값이 소실(0)되는 경우를 탐지
TensorMergeError 여러 입력을 병합할 때 각 Tensor의 크기가 같은지 검증 (예: 3×3+3×3은 정상, 크기가 다르면 오류)
OutputDimensionError 최종 출력 레이어의 차원이 요구되는 형태인지 검증

클래스 설계

BlockIntellisense 클래스 다이어그램 (클릭 시 확대)
  • 추상 클래스 ModelErrorChecker를 상속한 오류 유형별 Checker(DimensionErrorChecker, OutputDimensionErrorCheck, TensorMergeErrorCheck, ValueErrorChecker)가 각자 check()를 구현합니다.
  • ErrorManager가 Checker들을 모아 errorCheck()로 모델 전체의 오류를 수집합니다.
  • 오류는 추상 클래스 ModelError(유형·블록 ID·라인·메시지)를 상속한 오류별 클래스로 표현하고, ErrorMessageManager가 사용자에게 보여줄 메시지를 생성합니다.
  • LayerManager가 패딩·풀링·합성곱·업샘플링·reshape 등 레이어별 출력 값 계산을 담당해 Checker가 공통으로 사용합니다.
  • 새 오류 유형이 필요하면 Checker와 Error 클래스를 추가하는 방식으로 확장할 수 있는 구조입니다.

2. BlockPreprocessor – 데이터셋 전처리 파이프라인

AI 모델 학습에 쓰이는 데이터셋을 자동으로 전처리하는 파이프라인을 구축했습니다.

BlockPreprocessor 클래스 다이어그램 (클릭 시 확대)
  • CIFAR-10 · CIFAR-100 · MNIST · Fashion-MNIST 등 기본 제공 데이터셋 전처리 지원
  • 사용자가 직접 데이터를 입력하는 Custom 데이터셋 전처리 지원
  • 모델 학습에 필요한 형태로 데이터를 변환해 이후 학습 단계에서 활용
  • 추상 클래스 Preprocesser를 상속한 데이터셋별 전처리 클래스를 DataBlockPreprocesserManager가 입력 설정에 따라 호출하는 구조

🔥 어려웠던 점 / 해결 방법

  • 문제: 머신러닝 사전 지식이 부족한 상태에서, 약 2주 안에 필요한 개념을 학습하고 프로젝트에 적용해야 했음. 특히 CNN의 Convolution · Pooling 연산을 직접 구현하는 과정이 어려웠음
  • 해결: 팀원의 도움으로 기본 개념을 빠르게 익힌 뒤, 구현을 통해 이해도를 높였음. 막히는 부분은 포기하지 않고 매달렸고, 하루를 투자해도 풀리지 않는 문제는 팀원과 함께 해결
  • 결과: 짧은 기간에 모르는 영역을 구현하며 학습하는 방식을 익힘

🌱 결과 및 배운 점

  • CNN의 Convolution · Pooling 등 레이어를 직접 구현했고, Python 코드를 입력하면 해당 코드에 맞는 레이어 블록을 생성하는 기능까지 구현했습니다.
  • 백지에서 코드를 직접 구현하는 데 느낀 한계를 완전히 넘지는 못했지만, 팀워크의 중요성을 깨달았습니다.
  • 서비스 종료된 유사 서비스에서 아이디어를 얻어, 교육 목적의 오류 인텔리센스 기능을 직접 설계해 본 경험이 되었습니다.
